# SCADA Simulator

A local synthetic industrial operations world for developers building, testing, and demoing SCADA monitoring integrations. One simulator publishes the same values through Modbus TCP, OPC UA, MQTT, and MCP, with a small operator UI and a separate live fleet map.

It models mining, power, water, manufacturing, buildings, and GPS-equipped vehicles: **32 areas, about 200 equipment units, and about 1,800 tags**. The mine electrical network, water network, copper concentrator, haulage fleet, underground ventilation, factory steam/instrument-air/production-line loops, and eight site buildings have explicit dynamic models; the remaining areas still use broad synthetic behavior. Inject incidents, observe alarm and signal-quality changes, and connect your own telemetry readers.

Analog tags in the remaining synthetic areas include small, deterministic three-second correlated transmitter noise keyed by simulation seed and tag. Discrete states remain exact, tag ordering does not change a reading, and noise does not feed back into the modeled equipment.

> Everything here is simulated. It is not a PLC, a process engineering model, a safety system, or a connection to real equipment.

## Quick start

Requirements: Python 3.10+ and a local machine. The map uses public OpenStreetMap tiles, so its basemap needs an internet connection.

```bash
git clone https://github.com/alonsoburon/scada-simulator.git
cd scada-simulator
./setup.sh
./start_playground.sh
```

Open <http://127.0.0.1:8501> and keep the dashboard page open while using MCP simulation controls. The page starts the synthetic plant session; the other services start alongside it. Use the sidebar to start/stop the whole plant, set simulation speed, and inject an incident. Stop all services with Ctrl+C.

## Integration endpoints

All endpoints bind to loopback (`127.0.0.1`) by default. They have no authentication and are intended for isolated local development only.

| Interface | Endpoint | What it exposes |
| --- | --- | --- |
| Modbus TCP | `127.0.0.1:1502`, unit 1 | FC04 input registers; three per tag: IEEE-754 float32 high word, low word, quality code (`0=GOOD`, `1=STALE`, `2=BAD`). The generated tag/address map is at `scada_playground/.runtime/modbus_register_map.csv`. |
| OPC UA | `opc.tcp://127.0.0.1:4840/factory/server/` | `Objects/Factory/<area>/<asset>/<tag>/{Value,Quality,Units}`. |
| MQTT | `127.0.0.1:1883` | Retained area batches at `scada/factory/areas/<area_slug>/telemetry`, plus plant status and alarm snapshots under `scada/factory/`. |
| MCP Streamable HTTP | `http://127.0.0.1:8503/mcp` | Discover/read plant data and trigger simulator-only scenarios. |
| MCP stdio | `scada_playground/mcp_server.py` | Same MCP tools for a host that launches local subprocess servers. |
| Fleet map | `http://127.0.0.1:8502/map` | Independent Leaflet map updated by WebSocket; pan and zoom persist while vehicles move. |

The protocol gateway updates from the same atomic snapshot as the dashboard. For normal SCADA reader development, use Modbus, OPC UA, or MQTT. MCP is a companion surface for compatible agents and applications that need structured discovery, queries, or test-scenario control.

MCP tag reads show the canonical simulator snapshot. Protocol faults are applied independently inside each protocol adapter, so inspect Modbus/OPC UA/MQTT to observe a protocol fault's effect.

## MCP tools

- `get_plant_status`, `list_systems`, `list_scenarios`: discover the simulator, valid incidents, and built-in replays.
- `search_tags`: filter tags by substring, area, asset, or quality; paginated.
- `read_tags`: read up to 200 exact tag IDs from one snapshot. Each sample includes units, engineering limits, quality, and timestamp.
- `get_alarms`, `get_fleet_positions`: read alarm records and simulated vehicle locations/state.
- `get_haulage_state`: read truck cycle states, delivery rate, payload/fuel tags, and ROM dispatch holds.
- `get_water_network_state`: read water tank inventories, pipe flows, pressure, demand, and spill.
- `get_water_distribution_state`: read elevated-tank inventory, district pressure and service, water age, turbidity, chlorine residual, leakage, and non-revenue water.
- `get_wastewater_state`: read equalization, chemical inventories, treatment performance, effluent quality, reuse, outfall, and sludge state.
- `get_concentrator_state`: read ore buffers, grinding limits, product size, recovery, water use, and power.
- `get_process_control_state`, `control_process`: inspect the simulated process sequence and request orderly `START`, `STOP`, or `RESET_TRIPS` after the cause clears.
- `get_power_network_state`: read grid import, diesel/solar/storage dispatch, frequency, voltage, load shedding, and feeder limits.
- `get_plant_utilities_state`: read boiler output, steam-header pressure, condensate return, compressor output, receiver pressure, dryer dew point, CIP phase/chemistry, and downstream production.
- `get_chilled_water_state`: read chiller output and COP, chilled-water storage, supply/return temperatures, cooling duty, and service to pasteurizer product cooling.
- `get_site_buildings_state`: read each building's thermal state, HVAC, occupancy, CO₂, ventilation, filter loading, and electrical load.
- `get_underground_ventilation_state`: read main-fan duty, airway flow and pressure, and district methane, NOx, oxygen, dust, and temperature.
- `start_cip_cycle`: request a simulated clean-in-place cycle for either pasteurizer; water, chemical, steam, power, and target availability permissives apply.
- `control_simulation`: `start`, `stop`, `reset`, `acknowledge_alarms`, or `inject_incident` with a selected type, severity, and area.
- `run_scenario`: reset and replay a named scenario from a seed; same seed replays the same measurements and timing.
- `step_simulation`: advance a paused run by an exact number of simulated seconds.
- `inject_protocol_fault`, `list_protocol_faults`, `clear_protocol_faults`: inject and manage per-protocol telemetry faults.
- Resources: `scada://plant/status`, `scada://plant/systems`, `scada://plant/scenarios`.

Control commands are applied by the active dashboard session and acknowledged only after its next snapshot is published. Keep at least one dashboard tab open; a command times out if no session processes it within 20 seconds. MCP cannot write to any industrial protocol endpoint or physical equipment.

### Connect an MCP client

For Streamable HTTP clients, use `http://127.0.0.1:8503/mcp` while the playground is running. For stdio clients, add a server entry like this to the client configuration, replacing the paths with the absolute path to your checkout:

```json
{
  "mcpServers": {
    "scada-simulator": {
      "command": "/path/to/scada-simulator/.venv/bin/python",
      "args": ["/path/to/scada-simulator/scada_playground/mcp_server.py"]
    }
  }
}
```

The stdio server reads the same snapshot and uses the same command mailbox. The dashboard session must be running to advance the simulation or apply control commands.

## Deterministic scenarios and edge cases

The sidebar's **Scenario replay** panel and the MCP `run_scenario` tool run a named scenario from a selected seed. The simulator resets first, records the seed and scenario timeline, and stops at the scenario's end. Stop to pause, use **Step +1 simulated second** (or `step_simulation`) to inspect a boundary, then run the same scenario and seed to replay it.

Built-in scenarios:

- `mine-grid-support-and-recovery`: a large transmission trip islands the mine grid, trips the process sequence, then simulates an operator reset and orderly restart after electrical supply recovers.
- `distribution-overcurrent-reclose`: a calculated three-phase feeder fault trips the IEC standard-inverse primary relay and reconnects once; a second fault with a deliberately failed breaker operates the coordinated distribution-incomer backup, isolates every feeder, then waits for the simulated operator to reset it.
- `haulage-crusher-buffer`: a long crusher conveyor trip lets discrete truck loads fill ROM and pause dispatch; recovery draws the stockpile down until truck loading resumes.
- `concentrator-mill-degradation`: changing ore hardness, geometallurgical block grade, grinding degradation, and a mine power disturbance propagate at different rates through stockpile blending, grind size, flotation recovery, water demand, and buffered inventories.
- `mine-water-pump-and-demand`: a process demand surge is followed by pump degradation; tank inventory, return flows, alarms, and recovery respond over time.
- `mine-water-treatment-upset-and-recovery`: source turbidity, chemical use, filtration loading, transfer-line delay, and treated-tank quality move at different rates during an upset and recovery.
- `water-distribution-outage-and-demand-recovery`: an isolated distribution-pump outage draws down the elevated tank; a demand surge lowers high-zone pressure before tank refill restores district service.
- `chilled-water-loss-and-recovery`: a chilled-water feeder loss draws down thermal reserve; depleted cooling capacity diverts hot product, drains the balance tank, and slows filling until cooling recovers.
- `boiler-header-pressure-and-recovery`: boiler capacity loss drains header inventory; pasteurizer temperatures lag the pressure drop and recover after the fault clears.
- `cip-water-steam-and-production-recovery`: a pasteurizer CIP cycle sequences rinse, caustic, hot sanitation, final rinse, and release; shared water or steam shortages hold the phase and production returns after cleaning.
- `cip-wastewater-quality-and-reuse`: CIP return enters equalization and treatment through an outage and recovery; compare neutralization, solids removal, chemical inventories, sludge pressing, quality-gated reuse, and outfall.
- `compressed-air-receiver-and-recovery`: compressor loss draws down receiver pressure, degrades dryer output, and curtails filler and case-packer rates before recovery.
- `site-buildings-hvac-outage-and-recovery`: a building-feeder outage stops HVAC, raises indoor temperature and CO₂, then follows restart delays and air-quality recovery after power returns.
- `underground-ventilation-loss-and-recovery`: a main-fan feeder outage starves the underground air circuit; district contaminants and heat lag airflow, then clear after fan restart.
- `packaging-jam-buffer-and-recovery`: a case-packer jam fills the accumulation conveyor, backs the filler up, fills the pasteurized-product tank, and propagates a controlled slowdown back upstream before draining on recovery.
- `grid-comms-recovery`: simulated network partition in Grid distribution, stale quality, then recovery.
- `frozen-signal`: freeze one signal while simulation time and other values continue.
- `mqtt-tag-gap`: omit one tag from MQTT batches temporarily, then restore it.

The protocol fault injector supports `stale`, `bad`, `freeze`, and `suppress`, targeted at an area or exact tag and scoped to Modbus TCP, OPC UA, MQTT, or all. Durations are in simulated seconds; `0` means keep the fault active until cleared. `freeze` holds the value while retaining GOOD quality, which is useful for stuck-sensor detection. `suppress` omits a tag from MQTT batches. Because Modbus register addresses and OPC UA nodes are stable, those two protocols keep the tag present and report BAD quality for a suppressed tag. Faults change protocol output only; the canonical process values remain untouched.

For an edge-case drill, run `mqtt-tag-gap` with seed `17`, subscribe to the Grid distribution area topic, and confirm the selected tag disappears and later reappears. Run `frozen-signal`, compare the selected tag through all three protocols while the simulation clock advances, and confirm that clearing the fault lets its value move again.

## Scenarios and tag data

The included incident types are Signal drift, Network partition, Utility loss, Mechanical degradation, Process upset, Conveyor jam, Electrical fault, and Water main leak. Electrical fault must target one named distribution feeder; it also accepts a position from 0% (source end) to 100% (far end) and an optional primary-breaker failure. Water main leak must target one district in Water distribution; severity selects a 5, 15, or 32 mm equivalent orifice whose pressure-driven discharge competes with customer service. Each type has Small, Medium, and Large severity. Signal drift targets one analog instrument and adds a reproducible bias ramp while the reading remains `GOOD`, modeling a plausible but incorrect transmitter. If a control loop uses that tag, the loop follows the bad measurement and changes the real process; peer instruments remain independent. Choose a tag in the UI or pass `target_tag` to MCP `control_simulation`; without one, the simulator selects a reproducible point in the chosen area. A network partition marks affected readings `STALE`; the effect clears when its simulated duration expires or the simulation is reset. A locked-out feeder or distribution incomer can be manually reset from the Power network tab or with the MCP `control_simulation` action `reset_feeder_protection`, after its active fault has cleared.

Mechanical degradation of concentrator equipment now accumulates condition loss while the affected asset is operating. Clearing the incident removes its immediate fault effect but does not restore health; vibration and effective capacity retain a condition-related offset. The process PLC panel shows condition for crusher, conveyors, mills, flotation, thickening, and filtration. Stop the process sequence until the asset is stopped, clear the mechanical fault, then use **Perform maintenance**; MCP clients can request `control_simulation(action="maintain_equipment", target_asset="SAG mill")` under the same stopped-and-clear conditions. This is a compact maintenance exercise, not a remaining-useful-life or work-order model.

## Mine water flow simulation

The **Water network** tab models a north reservoir, raw-water tank, process-water tank, reclaim pond, treated-water tank, concentrator reclaim sump, and shared wastewater equalization and treatment tanks. It advances at one-second simulation steps. Pipe flow is solved from Darcy–Weisbach wall friction, minor losses, elevation head, valve loss, and a quadratic pump curve. Full-pipe transport queues add travel-time lag while preserving inventory, including a separate quality front on the reclaim-to-treated transfer. A motor trip removes drive torque but the pump rotor coasts down with a pump-specific time constant, so pump head and flow decay over several scans. Each pumped line has a spring check valve: when downstream head overcomes pump head, the disc closes over its modeled travel time and permits a bounded return from the pump-side linepack. After it seats, that return stops while water already in the pipe keeps travelling toward the process tank. A low-compute one-dimensional characteristic wave layer moves pressure waves along about 20 m pipe cells at 0.02 s substeps, reflects them at fixed-head tanks and closed valves, and attenuates them with estimated pipe friction. Tags expose pressure at the source, midpoint and receiving end plus each scan's positive and negative extremes; those extremes feed transient pressure alarms. PI level controllers use their noisy transmitter process values and drive pump speed commands through VFD ramp limits; those water pressure, flow, level, and treatment measurements have a reproducible three-second correlated noise component; an injected drift on a level transmitter therefore biases its AUTO loop. Operators can switch each pump between AUTO and MANUAL, change tank setpoints or speed, and disable equipment. Tank volumes follow explicit mass balances; the model tracks site and concentrator gross demand, solids-derived recovery streams, fresh make-up, unmet demand, spill, pipe inventory, pump power, and motor current. Concentrator tailings overflow and filter-press filtrate enter the reclaim sump, then return through a dedicated pump and delayed pipe; fresh make-up is gross process demand minus those returns. Service water passes through chemical conditioning, filtration, and disinfection before it reaches the treated tank. Turbidity, chlorine residual, finite chemical inventory, filter loading, differential pressure, and backwash demand evolve over time; backwash draws water from the finite treated tank and carries modeled filter solids into the wastewater train. Factory CIP return joins backwash water in equalization, then feeds a finite reaction tank sized for a 20-minute design hydraulic residence time. That tank adds a mixing and quality lag ahead of pH neutralization, DAF solids removal, sludge pressing, quality-gated reuse to the reclaim pond, and outfall. Utility loss, mechanical degradation, and process upset alter flows, inventories, and effluent quality. Wastewater power loss and limited equalization headroom can constrain upstream discharges; the `get_wastewater_state` MCP tool exposes the treatment state and the scenario `cip-wastewater-quality-and-reuse` exercises outage and recovery. Pressure, flow, tank, and treatment measurements receive small first-order-correlated noise keyed by seed, tag, and simulation scan. A replay reproduces the same readings, and rendering a tag twice in one scan does not draw a second sample.

Use the simulated pump and valve controls to create operating changes. The diagram encodes flow with line width and direction; trends show storage, demand, flow, treated-water quality, and filter loading over simulated time. Scenario `mine-water-pump-and-demand` provides a deterministic demand and pump degradation replay; `mine-water-treatment-upset-and-recovery` shows the delayed response to a source-quality disturbance.

Mechanical degradation now accumulates condition loss on running mine-water pumps and remains after the incident clears. The pump table exposes health separately from its active performance factor. Disable a pump and wait for VFD speed and rotor coastdown to reach zero before using **Maintain water pump**; an active mechanical fault blocks the repair. MCP clients can use `control_simulation(action="maintain_water_pump", target_asset="Process feed pump")` with the same isolation requirements. This is a compact work practice, not a pump overhaul or reliability-centered maintenance model.

Treated water now feeds a finite elevated service tank through a VFD-controlled refill pump. Three districts use tank elevation, Darcy–Weisbach branch losses, pressure-reducing valves, and pressure-dependent customer demand; background leakage scales with pressure, so low pressure first curtails customer delivery and then reduces leakage. A targeted Water main leak adds a separate pressure-driven orifice discharge; mechanical degradation of the refill pump reduces its capacity but does not alter pipe leakage. A scan-level head constraint prevents reported delivery from exceeding the finite water inventory. Chlorine decays with estimated branch residence time, while tank turbidity mixes incoming quality and settles slowly, with process upsets able to resuspend solids. These are compact approximations, not calibrated water-quality or distribution-network solvers. The tank is included in the site-wide water mass balance, the refill pump load feeds the mine electrical request, and its local feeder can fail without stopping treatment or the mine-water pumps. District pressure, customer service, leaks, water age, turbidity, chlorine residual, and the refill pump are available as `water_distribution.*` SCADA tags and through MCP `get_water_distribution_state`. Run `water-distribution-outage-and-demand-recovery` to follow the storage and pressure lag, demand surge, and a large district-main break. In the incident panel or MCP `control_simulation`, target `Water distribution` and one district zone to inject a 5, 15, or 32 mm equivalent break.

District elevations, service curves, pipe dimensions, leak coefficients, daily demand shape, tank geometry, and chlorine decay rate are assumed exercise parameters. The network is a lumped branch model; it does not calculate a calibrated city-scale topology, fire-flow transients, contamination transport, or utility-specific pressure standards.

This remains a compact learning model. Pipe friction and pump curves are simplified steady-state relationships; transport queues approximate plug flow. Rotor coast-down and check-valve travel times use assumed values, not measured motor/pump inertia or valve-disc dynamics. Endpoint pressure waves now alter the head available to the following one-second flow solve, but the hydraulic boundary flow is not re-solved at the wave layer's 0.02-second step. It therefore is not a fully coupled nonlinear transient solver or a calibrated method-of-characteristics network model. A seated check valve requires residual rotor motion to reopen; this prevents a pressure-only numerical wave from creating sustained pump flow. Absolute pressure adds an assumed 70 kPa site atmosphere and compares against water's vapor pressure to flag a column-separation risk; it does not form or collapse a vapor cavity. The fixed pipe pressure rating, assumed wave speed, pressure profile, reflection coefficients, and friction damping are not site-calibrated. Service-water and wastewater chemistry, DAF removal, and reuse quality limits are bounded training dynamics, not validated treatment design or discharge-compliance calculations. It does not model pipe elevation profiles, changing pipe diameter, vapor-cavity formation/collapse, pump efficiency maps, detailed flocculation/settling, or site-calibrated equipment. The mine power feeder includes service-water and wastewater treatment loads alongside the water pumps.

## Factory steam and instrument-air utilities

The chilled-water plant is modeled separately from steam and compressed air. Two chillers dispatch against a pasteurizer cooling duty calculated from hot-product flow and sensible heat; individual chiller availability, ambient condenser temperature, COP, pump flow, and a finite thermal store determine cooling service. A fully de-energized compressor trips immediately and derated output stays within available capacity; the thermal store carries cooling duty while compressors are unavailable. If cooling is inadequate, hot pasteurized product is diverted before it enters the product buffer, then the filler slows after the buffer drains. The heat capacity, product mass per unit, chiller ratings, tank reserve, and approach temperature are configurable training assumptions, not site-specific design values. Scenario `chilled-water-loss-and-recovery` makes the thermal reserve and downstream production lag visible.

The **Plant utilities** tab models two boilers feeding a finite steam header, a delayed condensate return, two air compressors, a dryer, a receiver plus effective ring-main linepack, and a coupled production line. Pasteurizers only send product above a simulated minimum temperature; colder output is diverted. A finite pasteurized-product tank buffers the fillers, and a finite accumulation conveyor buffers the case packer. Each scan conserves product across those two inventories; when downstream blockage fills them, filler and pasteurizer output back off. A case contains three simulated units. Header, receiver, and product inventory buffer outages; boiler/compressor/packer output ramps; low pressure curtails pasteurizer temperature and packaging rates with thermal and pneumatic response lags. Condensate reuse and boiler make-up change after the return delay. Compressor electrical demand is included in the site power request, so a mine-grid limitation can also reduce instrument-air capacity. A seven-phase clean-in-place cycle takes one pasteurizer out of service while the parallel line continues; phase timers wait on shared water, steam, and electrical availability. Caustic/sanitizer inventory and return pH/conductivity provide operator signals, CIP effluent is accounted in the water network, and the cycle exposes start permissives and low-inventory/starvation alarms.

The compressed-air receiver converts normal-volume inventory to gauge pressure with the ideal gas law at a fixed assumed 20 °C receiver temperature; its 8 bar(g) pressure limit defines the stored-air percentage. The steam header derives gauge pressure from steam mass at fixed volume and temperature, calibrated to 1 tonne at 8 bar(g), and relieves excess inventory at 10 bar(g). Analog tags use deterministic three-second correlated transmitter noise; binary sequence and compliance states remain exact. These compact inventory and pressure-control models do not calculate combustion, full steam tables, compressor maps, air-leak location, water-treatment chemistry, or pipe-network design. CIP dosing, pH, conductivity, and effluent are simplified educational signals, not validated cleaning recipes or wastewater compliance calculations. They provide cross-system failure propagation for SCADA monitoring practice. Run `boiler-header-pressure-and-recovery`, `compressed-air-receiver-and-recovery`, and `cip-water-steam-and-production-recovery` to compare stored inventory with downstream response.

## Copper concentrator process simulation

The **Mineral process** tab follows a copper-ore circuit from ROM feed through primary crushing, crushed-ore stockpile, SAG mill, ball mill/cyclone recirculation, flotation, concentrate thickening, cyclic filter pressing, a concentrate cake stockpile, tailings thickening, and tailings pumping. ROM, crushed-ore, concentrate, cake, and tailings inventories carry material through upstream and downstream stoppages. Copper is balanced separately through the mine feed, ROM, crushed-ore and SAG buffers, a six-cell well-mixed flotation bank, concentrate thickening/filtering/shipping, and tailings thickening/pumping. Changing geometallurgical blocks blend through inventory instead of appearing instantly at flotation; block grade variation is seeded and repeatable. The flotation cells retain copper between scans and respond to residence time, grind size, air, reagent, water availability, and mechanical condition. A severe crusher jam closes reclaim and preserves ROM inventory; the crusher also backs off when the finite crushed-ore stockpile is full. A bounded change in ore hardness alters specific energy and grind size; available SAG/ball mill power and equipment condition limit fresh throughput. The plant power estimate includes mills, crushing, conveyors, flotation air, pumps, thickeners, filtration, and fixed auxiliaries; the same total feeds the mine-grid model and is exposed in process telemetry. ROM is fed by discrete payloads from the haul truck cycles below. Water shortage and feeder limits derate production and equipment capacity. The modeled process feeder is rated at 36 MW beneath the 39 MW mine transformer limit.

The model samples every simulated second, smooths slow process measurements, and adds repeatable measurement noise keyed by seed and tag. A Large conveyor jam stops ROM reclaim, but the crushed-ore stockpile temporarily shields the mill; a grinding fault changes mill capacity, vibration, grind size, and recovery. Large-motor current uses balanced three-phase input power at a nominal 6.6 kV, 0.90 power factor, and 0.95 efficiency; these are explicit teaching assumptions rather than a motor-start or equivalent-circuit study. The flotation bank uses six well-mixed copper inventories and fixed solids holdup from the nominal tank volume and pulp ratio; it does not resolve bubble-size distributions, mineral liberation, or cell hydrodynamics. Replay `concentrator-mill-degradation` to observe the effects and recovery. The MCP `get_concentrator_state` tool provides a process summary; regular tag reads expose individual measurements through the same interfaces as the rest of the plant.

The **Process PLC sequence** controls a teaching sequence for tailings pumping and thickening, concentrate thickening and filtration, flotation, grinding, conveyors, and primary crushing. It models downstream-first startup, orderly shutdown, utility permissives, three-second delayed trips, basic dependency interlocks, and manual trip reset. Its process-water startup permissive consumes the last scanned level-transmitter value, so a drifting transmitter can block a restart even while the physical tank level differs; the UI exposes both values. Each motor start adds an equipment-specific, exponentially decaying active-power transient to the mine-grid request; the resulting voltage, frequency, and reserve response is exposed through the `mine_power_network.process_motor_starts.starting_load` tag. This is a lightweight aggregate of starter and acceleration demand, not a motor equivalent-circuit or protection study. Filter pressing alternates filling, squeezing, and cake discharge; finite concentrate and tailings inventories constrain upstream feed when their outlet equipment is unavailable. Factory timeline start/stop controls only simulation time; process start/stop controls the simulated equipment sequence. Reset clears trips only after the simulated supply recovers and active jam/severe mechanical causes clear; a separate operator start is required afterward. This is a small ordinary process-control model, not a certified safety PLC or safety instrumented system.

This is a low-compute supervisory approximation, not a calibrated comminution or metallurgy model. Three size classes pass through energy-, work-index-, and condition-dependent breakage probabilities, then size-dependent cyclone partitions. Rejected coarse and intermediate material recirculates with fresh coarse feed; the class mix relaxes over a 15-minute circuit residence time. Overflow, circulating load, and P80 are derived from that mill/cyclone pass. Flotation uses an effective cell volume, calculated pulp residence time, and first-order recovery kinetics adjusted by size class, air, reagent dose, and water availability. This compact class balance omits particle fracture distributions, liberation/mineralogy, flotation-cell residence-time distributions, reagent chemistry, water chemistry, and site calibration. The copper mass balance and finite buffers are useful for integration, historian, alarm, and failure-propagation exercises; they are not suitable for production forecasts or equipment selection.

The water circuit uses an explicit first-pass solids/water split. Gross process use is 0.90 m³ per tonne of flotation feed. Water follows the measured concentrate/tailings dry-solids split; the tailings thickener holds a finite liquid inventory, removes underflow water with pumped solids, and releases overflow at a bounded hydraulic rate. It targets 68% underflow solids and returns 92% of overflow water; an outage therefore stores liquid and can create a reclaim surge during restart. The concentrate thickener targets 60% solids, and a filter-press batch retains water at 85% cake solids; filtrate accumulates during filling and is released over the 90-second squeeze. Those streams enter a finite reclaim sump and return through its own VFD pump and delayed pipe. The process tank is charged with gross demand and credits return only when it physically arrives, so a pump trip fills the sump and causes a delayed water shortage. All assumptions are exposed as state or tags and the component return flows close against gross use. The model still omits settling kinetics, particle-size effects, rheology, density variation, and site calibration, so its separation efficiencies are teaching assumptions rather than design values.

## Open-pit haulage

The **Mobile fleet** map and telemetry share a route-driven cycle for twelve haul trucks: shovel queue, loading, loaded travel, crusher queue, tipping, and empty return. One shared shovel and one shared dump bay serve trucks in FIFO order; trucks waiting for either resource creep along distinct approach-road positions at up to 3 km/h instead of overlapping at the destination. Queue lengths, the truck in service, per-truck queue position, and wait duration are published as SCADA tags. Route waypoints have a fictional elevation profile; grade changes loaded/empty travel speed and uphill fuel demand, with road grade and engine load exposed as signals. Per-truck payload, fuel, engine hours, tire/brake temperatures, and loads hauled follow the cycle. Ore grade is assigned as the shovel loads each second, blended across that truck's payload, and carried with the load to the ROM tip. The concentrator receives both delivered tonnes and their copper mass, so a grade change reaches ROM according to actual truck travel and stockpile blending. Each tip adds its payload to the concentrator ROM inventory. Dispatch holds when current ROM plus ore already committed on loaded trucks reaches 40,000 t; loading resumes below 34,000 t to avoid rapid stop/start chatter. This look-ahead avoids sending more loads than the finite stockpile can accept. At 15% fuel reserve, trucks refuel at the shovel queue and emit a low-fuel alarm. Fleet mechanical degradation slows travel time, and shovel/power incidents delay loading. Service trucks and buses remain synthetic route vehicles. Run `haulage-crusher-buffer` to observe shared-resource queues, payload delivery, stockpile buffering, crusher recovery, and dispatch holds; MCP `get_haulage_state` reports fleet states and process tags.

This remains a route abstraction: uphill speed is limited by gross truck mass, haul-road rolling resistance, engine power, and drivetrain efficiency; diesel use follows the resulting tractive power plus accessory demand. Downhill braking heat uses a simple energy and cooling balance with an assumed service-brake share. These are explicit teaching assumptions, not calibrated truck, retarder, or multi-axle brake models. It also omits tire failure probability, collision avoidance, autonomous dispatch optimization, shovel dig cycles, and calibrated fuel maps. Truck delivery is discrete, while the crusher and downstream process retain their own capacity limits.

## Underground mine ventilation

The underground mine model solves the shared exhaust-fan and airway operating point from quadratic fan curves, branch resistance, and common airway losses. Flow splits across two decline districts and the ore-pass circuit by hydraulic conductance. Each district has a finite air volume; methane emissions, diesel NOx, oxygen consumption, dust release, and heat therefore change with airflow and clear over air-change time instead of stepping instantly with a fault. Gas and airflow transmitter noise has a reproducible three-second correlation time, so repeated UI reads at the same scan do not create new samples. Two parallel VFD fans ramp speed and share load; loss of their feeder removes motor power while rotor speed and measured fan flow coast down, and mechanical degradation reduces fan head. Their motor power joins the mine process demand, so constrained grid dispatch can reduce available ventilation and ventilation demand feeds back into the grid. The MCP `get_underground_ventilation_state` tool exposes fan, branch, and time-series state. Replay `underground-ventilation-loss-and-recovery` to inspect alarm timing and the lag between airflow loss and contaminant clearance.

The network is a lumped teaching model: fan curves, branch resistance, gas emissions, dust, diesel exhaust, heat release, zone volumes, and airflow requirements are assumed and not calibrated to a mine plan or jurisdiction. It does not calculate detailed three-dimensional airway networks, regulator doors, blast re-entry, gas layering, or exposure compliance. The alarm limits are simulator exercise thresholds, not operating guidance.

## Site buildings

The control room, workshop, warehouse, laboratory, substation building, pump house, office block, and gatehouse track room temperature with a first-order heat balance, thermal mass, envelope losses, solar and equipment gains, occupancy, door infiltration, and outdoor conditions. Thermostat hysteresis and minimum run/off times control heating or cooling; ventilation responds to CO₂ and filter loading. HVAC load is submetered into the mine site's electrical request, so grid constraints and local building utility outages affect comfort and indoor air quality over time. These are assumed training parameters and lumped zones, not calibrated building energy or HVAC design models. Replay `site-buildings-hvac-outage-and-recovery` to compare the outage, thermal drift, CO₂ response, and restart.

## Mine electrical network

Grid generation, two transmission paths, substations, distribution feeders, and the mine substation publish values from a shared dispatch model. It carries about 44 MW of normal import capacity, variable solar output, two diesel units with a 20-second start delay and finite ramp, and a 20 MWh battery with a 6 MW inverter, asymmetric charge/discharge ramp rates, and 94% charge/discharge conversion efficiencies. Battery SOC reflects conversion losses; the resulting heat-equivalent loss is exposed as SCADA telemetry. The diesel governor and battery inverter provide separate frequency-droop responses, visible as individual telemetry signals. Frequency, relay logic, generator governor response, battery inverter response, battery energy integration, and the intertie balance advance in 100 ms substeps; dispatch targets refresh each one-second scan. The published load allocation uses the source output reached by the end of the scan. A final dispatch reconciliation uses that scan's calculated feeder I²R losses, imports available grid power to cover the measured loss, and sheds load in the existing priority order if the intertie is at its limit. Three underfrequency load-shedding stages disconnect successive process-load blocks after 200 ms below pickup, then restore one block at a time after frequency remains stable for 30 seconds. The model serves site auxiliaries, water pumps, factory utilities, the underground ventilation fans, and the concentrator subject to transformer and feeder limits. During scarcity it preserves essential controls, then water supply, then steam/compressed-air services, then concentrator process loads, and sheds flexible site auxiliaries last. Served/requested power and a distinct factory-utility feeder tag make this priority visible. Transformer top-oil and winding hot-spot temperatures have separate thermal time constants; staged cooling starts at rising oil temperatures, and a sustained hot spot derates the connected transfer limit. Four radial feeders estimate branch voltage drop, reactive flow, current, loading, and I²R losses; those losses are included in the source-to-load balance. Source voltage responds to active/reactive demand through an equivalent source impedance, and the capacitor bank uses a 10-second operating delay with separate low/high voltage thresholds. Frequency carries prior connected load through the first disturbed scan and admits restored load into the balance immediately, then reports rate of change and the run nadir. A Large `Utility loss` in Grid transmission trips the intertie and islands the mine bus; smaller events derate the import path. Targeting Grid distribution, Mine power network, or Grid generation exercises local feeder, transformer, or source constraints. Electrical analog transmitters use deterministic three-second correlated noise; discrete breaker and relay states remain exact, and measurement noise is excluded from the public model snapshot. Replay `mine-grid-support-and-recovery` to inspect reserves and recovery.

This is a low-compute balanced network approximation. Feeder voltage uses linearized DistFlow, not an iterative AC load-flow solver. Source voltage uses an assumed equivalent impedance and aggregate P/Q, and switched capacitor control uses fixed thresholds and a fixed delay, not a volt/var controller tuned to a utility or site. Three-phase fault current is estimated from a Thevenin source, feeder R/X impedance, selected fault resistance, and fault location; source strength is assumed as 400 MVA on the grid or a simplified inverter/diesel estimate while islanded. Small, Medium, and Large select higher-to-lower fault resistance. Each feeder has a standard-inverse relay and a 15-second automatic-reclose dead time; a persistent fault can retrip and lock out the branch. If the primary breaker is explicitly failed, a slower standard-inverse distribution-incomer backup relay trips after its coordination margin and isolates all feeders. The model omits phase-ground and unbalanced faults, sequence networks, DC offset and peak asymmetry, iterative AC load flow, relay tolerances, CT saturation, breaker operating time, and multiple downstream relay zones. Feeder-to-process service assignments remain simplified. Frequency integrates a balanced-network swing approximation in 100 ms steps with fixed damping, source droop curves, ramp-limited governor/inverter response, and a stiff utility reference; dispatch targets refresh at one-second intervals. It does not resolve electromechanical oscillations, sub-cycle inverter response, governor deadbands, or site-specific underfrequency relay zones and motor load behavior. Its three process shedding blocks are illustrative settings rather than a protection coordination study. Use this to exercise protection telemetry, alarms, reserve transitions, and process response; it is not suitable for setting real protection relays.

Tag IDs use `area.asset.signal`, for example `grid_distribution.feeder_north.line_voltage`. Values have explicit engineering units, limits, quality, last-change reason, and snapshot timestamp. GPS coordinates and roads are fictional and geographically positioned near Escondida only for context.

## Configuration and development

- `./setup.sh` creates `.venv` and installs the runtime dependencies.
- `./start_playground.sh` starts the Streamlit UI, protocol gateway, live map, and HTTP MCP server.
- `SCADA_SNAPSHOT_PATH` can point the stdio MCP server at a snapshot in a different checkout.
- `SCADA_COMMAND_DIR` can override the MCP command-mailbox directory.
- Runtime snapshots, register maps, command files, virtual environments, and secrets are ignored by Git.
- Run the fast deterministic model/fault tests with `./.venv/bin/python -m unittest discover -s tests -v`.

The runtime is split into focused modules: `process_model.py` advances unmodeled synthetic areas, `power_network.py` dispatches the mine electrical network, `water_network.py` handles mine-water hydraulics and level controllers, `underground_ventilation.py` solves primary fan/airway flow and district air quality, `concentrator.py` models ore processing, `plant_controller.py` executes a limited PLC-style equipment sequence, `haulage.py` models truck cycles, `scenarios.py` schedules deterministic runs, `protocol_faults.py` transforms each protocol's view, `protocol_gateway.py` serves the industrial interfaces, `mcp_server.py` provides MCP tools, and `app.py` supplies the UI. Power, water, underground ventilation, haulage, and mineral processing share explicit operating constraints and process connections; other areas still use generated behavioral heuristics. It does not model a full PLC program, complete protection system, or industrial security stack.

## Safety and network scope

The services are unauthenticated and bind to loopback. Do not expose these demo ports to a LAN, the internet, or a real industrial network. Do not connect this simulator to real actuators, production systems, or safety functions. A dashboard stop/reset control affects only in-memory synthetic state.
